# 고객 증가 가정 — 성장·버티기 구조 계획

**스택:** Supabase + Vercel + Kling + Railway(ffmpeg 워커)  
**원칙:** Vercel은 접수, Kling·Railway가 소화, Usage Cap이 원가와 Capa를 동시에 지킨다.

시각 요약: Cursor Canvas `ba-saas-scale-capacity-plan.canvas.tsx`

---

## 1. 설계 한 줄

고객이 늘수록 GPU를 미리 사지 않는다.  
**Cap으로 수요를 평활화 → Kling 쿼터를 돈으로 확대 → Railway 공유 큐로 병렬 확대 → 단가가 안 맞을 때만 멀티벤더·자체 GPU.**

---

## 2. Phase 로드맵

| Phase | 유료 고객 | 부하 감각 (Pro 월 25숏폼 가정) | 성공 정의 |
|-------|-----------|-------------------------------|-----------|
| **A** | 0–30 | 월 ~750 렌더 / 일 ~25 | 컨시어지·수동 폴백 가능 |
| **B** | 30–150 | 월 ~3,750 / 일 ~125 | 셀프서브 + MRR 존속선 |
| **C** | 150–400 | 월 ~10,000 / 일 ~330 | 큐 대기 p95 관리 |
| **D** | 400+ | 피크 동시 폭주 | 벤더 이중화 · 원가 재협상 |

실제 부하는 Starter 비중·미사용으로 더 낮을 수 있음. 계획은 **상한 부하** 기준으로 짠다.

### Phase A — 검증·수동 버팀
- 플랜별 Cap, 계정당 동시 잡 1–2
- 비싼 AI(Kling) / 싼 합성(FFmpeg) 경로 분리
- Railway 워커 1대 · 인메모리 큐 허용
- Kling 단일 키 + 일일 한도 모니터링
- 장애 시 컨시어지 수동 납품 유지

### Phase B — Default Alive (30–150)
- 초과 과금 팩(추가 숏폼) 출시
- 테넌트 rate limit + 실패/재시도 대시보드
- 주간 유닛이코노믹스: Kling 원가 vs ARPU
- Storage 수명 정책(원본·실패작 정리)
- Railway 수직 스케일 + 큐 적체 알람
- Kling 쿼터 상향 또는 보조 키
- 예약 렌더로 피크 평활화

### Phase C — 큐가 제품 (150–400)
| 영역 | From | To |
|------|------|-----|
| 워커 큐 | 인메모리 | DB/Redis 공유 큐 + 워커 N대 |
| Kling | 단일 의존 | 우선순위 큐(유료>체험) + 백오프 |
| UX | 동기 체감 | 대기열·ETA·알림톡 비동기 |
| 원가 | 평균만 | 플랜별 COGS 하드캡 알람 |
| 데이터 | 무기한 보관 | 티어별 보관·해상도 정책 |

### Phase D — 이중화 (400+)
- Kling + 대체 API / 템플릿-only 폴백 라우팅
- 자체 GPU는 **월 AI OpEx ≫ GPU 고정비 손익분기**일 때만
- 엔터·대행사는 전용 쿼터·별도 워커 풀

## 3. 항상 켜두는 4개 제어판

| 제어판 | 지표 | 액션 |
|--------|------|------|
| 수요 Cap | 계정당 월/일/동시 잡 | 한도 · 대기열 · 추가팩 |
| 공급 Capa | Kling 잔여 · 큐 깊이 · p95 대기 | 쿼터↑ · 워커↑ · 예약 렌더 |
| 원가 | 렌더당 원 · COGS/ARPU | 템플릿 비중↑ · Cap↓ · 단가 협상 |
| 신뢰 | 실패율 · 재시도 · 동의/블러 | 폴백 · 수동 에스컬레이션 |

## 4. 90일 실행 백로그

| 기간 | 할 일 | 완료 기준 |
|------|------|-----------|
| D1–30 | Cap·동시잡·사용량 대시보드 | 플랜 한도 강제 + 일일 Kling/워커 리포트 |

## 5. 초기 금지

- GPU 서버 선구매  
- 무제한 렌더 마케팅  
- Vercel에서 무거운 영상 처리  
- 공유 큐 없이 워커만 복제  

---

## 6. 성장과 인프라의 대응 관계

```
고객↑ → 청구·Cap으로 수요 상한 고정
     → Kling 쿼터·단가로 공급 구매
     → Railway 워커·공유 큐로 처리량↑
     → Supabase Storage/DB 플랜·수명 정책
     → (나중) 멀티벤더·GPU
```

Vercel은 트래픽·API 접수층으로만 키운다. **AI Capa의 본체는 Kling + Railway**다.
