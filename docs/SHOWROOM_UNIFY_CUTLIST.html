쇼룸 단일화 컷리스트

목표: 직원과 고객이 같은 공개 쇼룸을 보며 소통한다. 내부 쇼룸은 “두 번째 쇼룸”이 아니라, 운영 기능은 어드민으로 내린다.

원칙 한 줄
쇼룸 = 보기·설명·상담 화면은 /public/showroom 하나. 만들기·고치기·이름/공개 관리는 전부 어드민.
남김공개 쇼룸 경험
내림운영·편집·승인
폐기 후보내부 쇼룸 UI 이중화

지금 구조 (문제)

내부 쇼룸 /showroom

  • ShowroomPage (~3500줄)
  • 직원용 컨트롤·정렬·내부 현장명
  • 원래 의도: 직원+고객 같이 보기
  • 실제: 두 번째 UI로 고착

외부 쇼룸 /public/showroom

  • PublicShowroomExperience (~2500줄)
  • ABM · 채널톡 · 공개 표시명
  • 승인 블로그만 노출
  • 실제 고객·광고 랜딩

에너지 낭비 지점: site_name / canonical_site_name / external_display_name / broad_external_display_name 이중화, URL 키 매칭, 두 UI 유지보수.

남길 것 — 공개 쇼룸 (같이 보는 화면)

항목이유비고
KEEP 공개 쇼룸 UI 고객·직원 공통 뷰 /public/showroom (+ case/cardnews)
KEEP 고민 → B/A → 사례 상담·숏츠 랜딩의 증거 허브 thin 입구로 단순화 예정
KEEP 상담 CTA / 채널톡 퍼널 행동 단계 직원이 같이 볼 때도 동일
KEEP ABM 이벤트 이탈·회수 실측 대시보드는 어드민
KEEP /r/* · UTM 진입 숏츠·광고 합류점 현장/유형 직행
KEEP 승인된 사례·블로그 노출 고객에게 보여줄 정본만 미승인은 어드민에서만
KEEP 고객용 표시명 1개 소통용 이름 예: “압구정 관리형” — 코드 숨김

어드민으로 내릴 것 — 운영 화면

항목어디로이유
ADMIN 사진 입고·BA·메타 편집 광고 대기실 / 자산관리 쇼룸이 아님
ADMIN 내부 현장 코드 (site_name) 어드민 필드만 고객·상담 화면에서 제거
ADMIN 공개 표시명 편집 어드민 1필드 이중 UI에서 고치지 않음
ADMIN 노출 순서·공개/비공개 어드민 토글 쇼룸은 결과만 봄
ADMIN 케이스 작업실·블로그 승인 /admin/showroom-case-studio 이미 존재, 유지
ADMIN 숏츠 제작·론칭 광고 대기실 / 숏츠 검수 쇼룸과 분리
ADMIN ABM 대시보드 /admin/showroom-abm 분석은 직원 전용
ADMIN 미승인 블로그/초안 미리보기 작업실 미리보기 공개 쇼룸에 draft 모드 넣지 않음

폐기·축소 후보 — 이중화 제거

항목조치메모
CUT 내부 쇼룸을 “제품”으로 유지 대시보드 「내부 쇼룸」→ 공개 쇼룸으로 링크 변경 같이 보기 = 공개 URL
CUT ShowroomPage 독립 UX 장기 유지 단계적 폐기 / 리다이렉트 기능 이전 후 삭제
CUT 표시명 다층 구조 display_name(공개) + site_code(내부) 2개로 축소 broad/external/canonical 정리
CUT 내부·공개 URL 키 매핑 복잡도 공개 case 키 = 표시명/슬러그 단일 alias 헬퍼 축소 목표

추천 실행 순서 (작게)

Phase 0

정책 고정: “같이 보기 = 공개 쇼룸 URL”. 대시보드 버튼을 공개 쇼룸으로 바꾸고, 내부 쇼룸은 “레거시”로 표기.

Phase 1

이름 단순화: 상담·공개 화면에는 고객용 표시명만. 내부 코드는 어드민에서만 보이게.

Phase 2

내부 전용 조작 이전: 정렬·공개토글·표시명 편집이 아직 내부 쇼룸에만 있으면 어드민으로 옮김.

Phase 3

/showroom → /public/showroom 리다이렉트 후 ShowroomPage 제거. (퍼널 thin 입구 개편과 같이 가도 됨)

한 줄 결론

쇼룸을 두 개 둘 문제가 아니라, 공개 쇼룸 하나 + 어드민 운영으로 dur면 된다. 내부 쇼룸 UI는 목적(같이 보기)을 배반한 중복이다.
